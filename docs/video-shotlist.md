# Video Shotlist for Demo (SIH26168)
**Target Length:** 3-5 minutes
**Recording Environment:** Browser (running `npm run dev`), full screen.
**Notes:** Claims must stay strictly within verified code capabilities. Do not claim real-time Android app operation or high-rate external IMU capability, as these are future production targets. All metrics shown are generated by the pipeline from real IO-VNBD CSVs.

---

## 1. Problem Framing (0:00 - 0:30)

*   **Timestamp:** 0:00 - 0:15
    *   **On-Screen Action:** Static view of the app showing the "AstraNav-IDR" title, followed by a switch to the synthetic map view (CityMap) zoomed out.
    *   **Voiceover:** "Welcome to the AstraNav-IDR demonstration for Smart India Hackathon problem 26168. Current vehicle navigation systems fail when GNSS becomes degraded or denied—such as in tunnels or urban canyons. A bad GPS fix can enter before total signal loss, causing INS drift, heading errors, and wrong routing."
*   **Timestamp:** 0:15 - 0:30
    *   **On-Screen Action:** Mouse cursor hovers over the UI elements explaining the approach (Architecture view).
    *   **Voiceover:** "Our solution does not guess coordinates directly. It uses a virtual odometer powered by an AI-ML classifier to extract reliable motion states from smartphone sensors, anchoring a live 15-state Error-State EKF to maintain physically consistent navigation."

## 2. Synthetic Demo & Integrity Features (0:30 - 2:00)

*   **Timestamp:** 0:30 - 0:50
    *   **On-Screen Action:** Start the "Synthetic" Replay. Show the map with the vehicle moving normally under "TRUSTED GNSS".
    *   **Voiceover:** "We'll begin with a synthetic replay to demonstrate the system's core behavior. Here, the vehicle has trusted GNSS."
*   **Timestamp:** 0:50 - 1:15
    *   **On-Screen Action:** The replay enters "DEGRADED" and then a total GNSS "BLACKOUT" phase. Focus on the map showing the diverging tracks: INS drifting away versus our fused estimate staying on the road with its 2σ covariance ellipse and protection bound.
    *   **Voiceover:** "As we enter a degraded state and then a total blackout, watch the trajectories. The raw inertial navigation (INS) rapidly drifts. However, our fused estimate remains constrained by NHC, ZUPT, and learned motion aiding, bounded by an honest, growing integrity envelope."
*   **Timestamp:** 1:15 - 1:30
    *   **On-Screen Action:** Open the Replay Lab. Trigger a "Pothole" fault injection or toggle ablations. Observe the system's response.
    *   **Voiceover:** "Using the Replay Lab, we inject a pothole fault. The system detects the disturbance and inflates covariance, ensuring shocks don't corrupt the long-term navigation state. We can also toggle individual aiding constraints live to observe their isolated contribution."
*   **Timestamp:** 1:30 - 1:45
    *   **On-Screen Action:** Use the Event Ledger or press `Space` / `←` / `→` to scrub through the replay. Open Command Palette with `Ctrl+K`.
    *   **Voiceover:** "We can seamlessly scrub with arrow keys or jump anywhere using the Command Palette to inspect the exact moment GNSS was lost and how the filter responded."
*   **Timestamp:** 1:45 - 2:00
    *   **On-Screen Action:** Open the Evidence view and flip to the Architecture view.
    *   **Voiceover:** "Our Evidence view provides transparent metrics with JSON/CSV export. The architecture cleanly separates the Python feature extraction and classifier training from the live TypeScript navigation engine."

*   **Timestamp:** 2:00 - 2:15
    *   **On-Screen Action:** Switch the data source from "Synthetic" to "IO-VNBD" (Trip S1). Start replaying a segment.
    *   **Voiceover:** "Now we switch to real-world data from the IO-VNBD benchmark dataset, recorded on commercial smartphones in urban traffic."
*   **Timestamp:** 2:15 - 2:45
    *   **On-Screen Action:** Let the 60s-outage segment play. Highlight the live 15-state ES-EKF, route lock score, and ML-gated ZUPT.
    *   **Voiceover:** "In this 60-second real-world GNSS outage, our live 15-state ES-EKF runs in-browser at 10 Hz. Notice that ZUPT is strictly ML-gated—it applies zero velocity only when both the physical motion detector and the learned model agree the vehicle is stopped, preventing false stops on smooth roads."
*   **Timestamp:** 2:45 - 3:15
    *   **On-Screen Action:** Open the Compare view (A vs B comparator) and the Data view / Model Inspector.
    *   **Voiceover:** "In the Compare view, we see a direct head-to-head comparison between the classical baseline and AstraNav full system. In the Model Inspector, we inspect the real learned weight matrix and the evaluation metrics: the model is evaluated on a device-adapted temporal holdout, beating majority class across all trips."
*   **Timestamp:** 3:15 - 3:30

    *   **Voiceover:** "Diagnostics confirms that our live filter step time is well under half a millisecond, proving the computational feasibility of running this core on embedded hardware."
